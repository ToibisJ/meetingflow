# MeetingFlow

מערכת לניהול ותיאום פגישות ושיחות בארגון.

המערכת מנהלת את כל מחזור החיים של פגישה: בקשה, תיאום, מעקב, ביצוע, סיכום והיסטוריה.
היא נבנית מראש כמערכת רב־ארגונית, כך שכל ארגון הוא דייר נפרד ולעולם אינו רואה מידע של ארגון אחר.

---

## מחסנית טכנולוגית

```text
Next.js 15 (App Router) + TypeScript
Tailwind CSS v4
PostgreSQL + Prisma 7 (driver adapter: @prisma/adapter-pg)
Zod            — ולידציה
next-intl      — ריבוי שפות
bcryptjs       — גיבוב סיסמאות
```

## התקנה מקומית

שלב ראשון — התקנת חבילות:

```bash
npm install
```

שלב שני — יצירת קובץ משתני סביבה:

```bash
copy .env.example .env
```

שלב שלישי — מילוי מחרוזת ההתחברות למסד הנתונים בתוך הקובץ:

```text
.env
```

שלב רביעי — יצירת הטבלאות:

```bash
npx prisma migrate dev
```

שלב חמישי — הרצת השרת:

```bash
npm run dev
```

הכתובת המקומית:

```text
http://localhost:3000
```

## עקרונות שאסור לשבור

**בידוד בין ארגונים.** אין גישה ישירה למסד הנתונים משום מקום במוצר.
כל שאילתה עוברת דרך לקוח שמוזרק לו מזהה הארגון של המשתמש המחובר.
הקובץ הבא מותר לשימוש ישיר רק בהתחברות, בזריעת נתונים ובמשימות רקע:

```text
src/lib/db.ts
```

**מכונת מצבים אחת.** אין מקום בקוד שמעדכן סטטוס בקשה ישירות.
כל מעבר עובר דרך פונקציית מעבר אחת שבודקת חוקיות, בודקת הרשאה, כותבת אירוע
בציר הזמן, כותבת יומן ביקורת ושולחת התראה.

**יומן ביקורת אוטומטי.** התיעוד אינו נכתב ידנית בכל פונקציה, אלא בשכבת השירותים,
כך שאי אפשר לשכוח לתעד שינוי.

**עיצוב.** מקור האמת לעיצוב הוא:

```text
C:\Claude\DESIGN.md
```

הכיוון הוא זכוכית מחוספסת בחצות: רקע כמעט שחור, טקסט כחול־לבן, גבולות שיער
פנימיים בלבד, וסגול יחיד כצבע פעולה. אין להוסיף צבעים נוספים.

## יומן התקדמות

### שלב 1 — שלד ומערכת עיצוב

בוצע:

- הוקם פרויקט חדש עם ניתוב, תמיכה בעברית מימין לשמאל ובניית ייצור תקינה.
- נכתבה סכמת מסד הנתונים המלאה: 14 טבלאות, 13 טיפוסי ערכים מוגדרים ואינדקסים.
- הוטמעו טוקני מערכת העיצוב: צבעים, גופנים, מרווחים, פינות, צללים ורקע כחול הדפס.
- נוצר חיבור למסד הנתונים דרך מתאם הנהג של Prisma 7.
- הועלה לגיטהאב.

נשאר פתוח:

- מחרוזת ההתחברות למסד הנתונים בענן טרם התקבלה, ולכן הטבלאות טרם נוצרו בפועל.

### שלב 2 — שכבת הליבה

בוצע:

- בידוד בין ארגונים בהזרקה אוטומטית של מזהה הארגון לכל שאילתה.
- מטריצת הרשאות לארבעת התפקידים, ומסנן נראות ברמת השורה.
- מכונת מצבים של בקשת פגישה עם כל 12 הסטטוסים והמעברים החוקיים.
- יומן ביקורת אוטומטי ברמת השדה הבודד.
- ניהול הפעלות: סיסמאות מגובבות, ובמסד נשמר רק גיבוב של אסימון ההתחברות.
- מילון טקסטים מלא בעברית ובאנגלית.
- נתוני הדגמה לשני ארגונים, לצורך בדיקת בידוד.

### שלב 3 — שכבת הבינה המלאכותית

בוצע:

- שכבת ספק מופשטת. שום קוד מוצר אינו קורא לספק חיצוני ישירות.
- מנוע עדיפויות דטרמיניסטי: 11 אותות, ציון 0 עד 100, והסבר לכל נקודה.
- שער אחד שכל קריאה עוברת בו, ואוכף הרשאה, בידוד ארגון, תקציב ותיעוד.
- פלט מובנֶה בלבד, מאומת מול סכמה לפני שמירה.
- יומן שימוש ועלות לכל קריאה, ותקרת תקציב חודשית לפי תוכנית.
- יומן ביקורת של הבינה המלאכותית: מה הוצע, מה אדם שינה, ומי אישר.
- תשע יכולות: מרכז פיקוד, ניסוח הודעות, הכנה לפגישה, מבנֵה סיכומים,
  זיהוי המשך טיפול, זיהוי בקשות תקועות, זיהוי כפילויות, חיפוש בשפה חופשית
  ותקציר למנהלים.

עקרונות שנאכפים בקוד ולא בהמלצה:

- מסד הנתונים הוא מקור האמת. המודל אינו מקור אמת.
- כל מספר שמוצג מחושב במסד הנתונים ומועבר למודל כנתון סגור.
- חיפוש בשפה חופשית אינו מייצר שאילתה. המודל ממלא טופס סינון סגור,
  והקוד מריץ אותו יחד עם מסנן ההרשאות של המשתמש.
- פעולה משמעותית אינה מתבצעת בלי אישור אדם.
- בלי מפתח, כל לוח בינה מלאכותית מדווח שאינו זמין. אין תשובה מומצאת.
